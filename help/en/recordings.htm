Recording library, import and recovery

Back up the source before importing a legacy database or individual MFZR. Migration creates one file per flight; the index keeps metadata and a relative path. A missing file hides the recording without deleting its index entry. Check its location and restore it before removing metadata. Text search and group filters combine, so an empty result may reflect both filters.

The tree groups flights by aircraft ICAO, departure ICAO, year and localized month; newest flights come first. Missing files retain index metadata.

Option / actionBehavior and limitations
Search / groupsCombine the text search and group filter. Clear them to restore results. A folder is a grouping, not an individual recording.
Open / refreshOpen selects a recording database/index. Refresh reloads the library and discovers .mfzr files in recording storage.
ImportAccepts individual .mfzr files, legacy flight_data.db and the original Qt-recorder database. Legacy flights become separate recordings; the source is preserved and repeat imports avoid existing entries.
Legacy exportExports one flight with fields supported by the original recorder. SDK, FMC, weather and other FDR extensions are omitted, so it is not a full backup.
GroupsCreate, rename, delete and assign groups. Confirm assignment with OK. Deleting a group is distinct from deleting a flight.
Flight informationInspect/edit the metadata offered by the dialog. Type and departure determine grouping; telemetry remains the source for replay.
DeleteConfirmation removes the selected recording file and its index entry. Stop recording it first. This is not just hiding an item.
RecoveryStartup can offer recovery after a crash. The result may be partial or damaged. Preserve a backup before repairing valuable data; a recovered file is not proof of a complete flight.
Single-file previewStart MSFS2024-FDR.exe with an existing .mfzr path. Only that flight appears; the library is hidden, management/recording are disabled and SimConnect is not opened.
