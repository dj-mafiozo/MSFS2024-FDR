Recording a simulator flight

Automatic recording needs an actual flight start, not just connection, AircraftLoaded or preparation. Session end closes and finalizes the file; finalizing is not completed. Shorter intervals increase samples, workload and size but cannot force an addon to publish SDK data faster. After a CTD preserve the recoverable file until its ending has been inspected.

Recording actions require a supported MSFS 2024 connection. Loading an aircraft or showing preparation screens is not enough.

Option / actionBehavior and limitations
StartManually starts capture for the active, ready flight when enabled. If disabled, check simulator version, connection and Ready for flight.
StopEnds capture and finalizes the recording. Wait for completion before moving the file or closing. Active recordings cannot be deleted or opened as completed flights.
Automatic recordingWaits for an active flight after Ready for flight, not the preparation screen. Simulator/aircraft session events are considered. After a CTD inspect status and recovery on the next launch.
Sampling intervalThe toolbar value is milliseconds. Smaller intervals create more data and processing. New files retain the configured interval; old files use inferred spacing or a 500 ms fallback.
Aircraft dataSubscriptions follow the active aircraft and engine type. Selecting another display does not create missing SDK/L-var telemetry.
Statusesrecording is active capture; finalizing is file completion; completed is normal completion. interrupted/error need inspection. The Recording heading denotes an unavailable active entry.
Offline replayA connection failure while MSFS is closed does not invalidate an already loaded offline recording.
