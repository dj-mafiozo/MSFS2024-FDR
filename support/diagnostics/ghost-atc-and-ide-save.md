# Ghost, native ATC and Delphi project save

Ghost: use the four existing actions. It plays independently from the chart timeline, initially starting at the displayed recording time. Stop, selecting another recording or closing the application removes the owned object and closes the thread-owned connection. Settings > Ghost replay selects 5–60 Hz (30 by default) and an optional FSLTL_Rules.vmr path. The VMR is only a matching hint: the model/livery must be enumerated by the connected MSFS24. Prefer exact FSLTL models; B38M can fall back to B738; installed AIPlane/airtraffic models are fallback candidates. No models are downloaded. Heavy addon aircraft are excluded.

The thread imports only trajectory and available visual data into SQLite :memory:. Continuous channels interpolate; missing channels stay missing, discrete states hold, and gaps are not interpolated. Model-specific non-writable animations are disabled after an exception. Old recordings cannot recover unrecorded animations; existing gear and N1 can serve as visual fallbacks. New recordings include flap/gear/RPM animation channels. Lights use the recorded bitmask and object-targeted SET events. Test results are mocks, not a live aircraft compatibility claim.

Native ATC: install the updated optional Community bridge and keep its toolbar panel open/minimized. JS_LISTENER_ATC / ATCDialogLine sends text and raw payload to /atc/messages. Messages use recording time and replay with the existing ATC tab and 30-second slider caption. Separate NativeATCState rows preserve clearances, assigned altitude, runways, future agent and COM station fields. Simulator JS listener documentation is incomplete; raw payloads are retained for live verification.

References: [MSFS ATC listener](https://docs.flightsimulator.com/html/Programming_Tools/JavaScript/Coherent_Listeners/JS_LISTENER_ATC.htm), [MSFS24 AI API](https://docs.flightsimulator.com/msfs2024/retail/programming-apis/simconnect/api-reference/ai-object/).
